## 1.1 导数就是敏感度

先看一个再普通不过的二次函数：

$$f(x) = 3x^2 - 4x + 5$$

把它写成 Python 函数，并画出图像：

```python
# Listing 1.1 一个标量函数及其图像
import numpy as np
import matplotlib.pyplot as plt

def f(x):
    return 3*x**2 - 4*x + 5

print(f(3.0))

xs = np.arange(-5, 5, 0.25)
ys = f(xs)
plt.plot(xs, ys)
```

```
20.0
```

<div style="text-align: center;">
    <img src="Image/ch01/function-plot.png" width="45%" />
</div>

导数的含义，不是背公式，而是**敏感度**：如果我把输入 $x$ 轻轻推动一点点，输出 $f(x)$ 会跟着变化多少？变化的比例就是导数。

最直白的测量方法是：给 $x$ 加上一个很小的增量 $h$，看输出改变了多少，再除以 $h$：

$$f'(x) \approx \frac{f(x+h) - f(x)}{h}$$

在代码里试一下：

```python
# Listing 1.2 用数值方法估计导数
h = 0.000001
x = 2/3
(f(x + h) - f(x)) / h
```

```
2.999378523327323e-06
```

结果约等于 $3 \times 10^{-6}$，也就是约等于 0。这并不是代码出错。对 $f(x)=3x^2-4x+5$ 求导得到 $f'(x)=6x-4$，在 $x=2/3$ 处恰好为 0——这里是抛物线的谷底。数值结果之所以不是精确的 0，是因为浮点数只有有限精度，$h$ 太小或太大都会带来误差。这个微小的残差反而提醒我们：**数值求导只能近似，真正的梯度需要解析地算**。

当函数有多个输入时，导数的概念自然扩展为**偏导数**：固定其他输入，只看某一个输入变化时输出的敏感度。例如：

```python
# Listing 1.3 多输入函数的数值偏导
a = 2.0
b = -3.0
c = 10.0
d = a*b + c
print(d)

h = 0.0001
d1 = a*b + c
c += h
d2 = a*b + c
print('d1', d1)
print('d2', d2)
print('slope', (d2 - d1)/h)
```

```
4.0
d1 4.0
d2 4.0001
slope 0.9999999999976694
```

$\partial d/\partial c \approx 1$，符合直觉：$c$ 每增加 1，$d$ 就增加 1。同样可以测出 $\partial d/\partial a = b = -3$，$\partial d/\partial b = a = 2$。

手工这样一个个测下去，对于只有三个输入的小函数尚且可行；但神经网络有数百万个参数，显然不能靠“逐个加 $h$ 再相减”来训练。我们需要一种系统化的方法，把整个表达式的导数一次性算出来——这就是计算图和反向传播。

## 1.2 把表达式变成计算图

考虑下面这个稍微复杂一点的表达式：

$$L = (a \cdot b + c) \cdot f$$

其中 $a, b, c, f$ 是输入。它可以拆成一系列**只包含一个运算**的中间步骤：

$$e = a \cdot b,\quad d = e + c,\quad L = d \cdot f$$

每一步的输出都成为下一步的输入，天然构成一张有向图：叶子节点是输入，中间节点是运算结果，箭头表示数据流向。这就是**计算图**（computation graph）。

<div style="text-align: center;">
    <img src="Image/ch01/graph-computation-L.svg" width="85%" />
</div>

有了计算图，求导就可以只在**局部**进行。以 $\partial L/\partial a$ 为例，沿着从 $a$ 到 $L$ 的路径，把每一步的局部导数相乘：

$$\frac{\partial L}{\partial a}
= \frac{\partial L}{\partial d}\cdot\frac{\partial d}{\partial e}\cdot\frac{\partial e}{\partial a}
= f \cdot 1 \cdot b
= (-2)\times 1\times(-3) = 6$$

这就是**链式法则**。注意每个局部导数都非常简单：

+ 加法 $d = e + c$：对任一输入的偏导都是 1
+ 乘法 $e = a \cdot b$：对 $a$ 的偏导是 $b$，对 $b$ 的偏导是 $a$
+ 乘法 $L = d \cdot f$：对 $d$ 的偏导是 $f$，对 $f$ 的偏导是 $d$

复杂的全局导数，被分解成一串简单的局部导数。反向传播要做的，就是把这张图**从输出往输入倒着走一遍**，在每一步套用局部规则，并把结果累乘起来。

## 1.3 Value 类：让每个数记住自己从哪里来

要用代码实现这套机制，关键是让每个数值都知道三件事：

1. 自己的值是多少；
2. 自己是由哪些值、经过什么运算得到的；
3. 当上游把梯度传回来时，该如何把梯度分给这些“上游”。

micrograd 用一个小小的 `Value` 类封装了标量。下面是本章要用到的完整版本：

```python
# Listing 1.4 micrograd 的 Value 类
import math

class Value:

    def __init__(self, data, _children=(), _op='', label=''):
        self.data = data
        self.grad = 0.0                      #A
        self._backward = lambda: None        #B
        self._prev = set(_children)          #C
        self._op = _op                       #D
        self.label = label                   #E

    def __repr__(self):
        return f"Value(data={self.data})"

    def __add__(self, other):
        out = Value(self.data + other.data, (self, other), '+')

        def _backward():
            self.grad += 1.0 * out.grad
            other.grad += 1.0 * out.grad
        out._backward = _backward

        return out

    def __mul__(self, other):
        out = Value(self.data * other.data, (self, other), '*')

        def _backward():
            self.grad += other.data * out.grad
            other.grad += self.data * out.grad
        out._backward = _backward

        return out

    def tanh(self):
        x = self.data
        t = (math.exp(2*x) - 1)/(math.exp(2*x) + 1)
        out = Value(t, (self, ), 'tanh')

        def _backward():
            self.grad += (1 - t**2) * out.grad
        out._backward = _backward

        return out

    def backward(self):
        topo = []
        visited = set()
        def build_topo(v):
            if v not in visited:
                visited.add(v)
                for child in v._prev:
                    build_topo(child)
                topo.append(v)
        build_topo(self)

        self.grad = 1.0
        for node in reversed(topo):
            node._backward()

#A 梯度初始化为 0，之后通过 += 累加
#B 每个节点默认的“反向函数”什么都不做
#C 记录产生当前节点的子节点
#D 记录产生当前节点的运算类型，方便画图
#E 给节点起名字，方便调试和可视化
```

代码不长，但每一处设计都有讲究。我们逐个拆开看。

**`data` 与 `grad`。** `data` 保存标量值，`grad` 保存损失对这个值的导数。`grad` 初始为 0，最终会被累加。

**`_prev`。** 保存产生当前节点的子节点集合。例如 `d = e + c` 得到的 `d`，其 `_prev` 是 `{e, c}`。整个计算图就是靠这个指针网络串起来的。

**运算符重载。** Python 中的 `a + b` 会调用 `a.__add__(b)`，`a * b` 会调用 `a.__mul__(b)`。只要让 `Value` 实现这两个方法，就能用最自然的语法构建计算图，而不必写成 `add(a, b)` 这样的函数调用。

**闭包 `_backward`。** 这是整个类最精巧的地方。每次做加法时，我们创建一个临时函数，把 `self`、`other`、`out` 三个变量“记住”。这个函数知道局部导数规则：加法的导数是 1，乘法的导数是对方的值。但它**不立刻执行**，只是挂在 `out._backward` 上，等反向传播时再调用。

**为什么用 `+=` 而不是 `=`。** 一个节点可能被使用多次（后面 1.7 节会看到），每次使用都会贡献一份梯度。按照多元链式法则，所有路径的贡献必须**相加**。这一点是初学者实现自动微分时最容易写错的地方。

现在用这个类搭出刚才的表达式：

```python
# Listing 1.5 用 Value 构建表达式 L = (a*b + c) * f
a = Value(2.0, label='a')
b = Value(-3.0, label='b')
c = Value(10.0, label='c')
e = a*b; e.label = 'e'
d = e + c; d.label = 'd'
f = Value(-2.0, label='f')
L = d * f; L.label = 'L'
L
```

```
Value(data=-8.0)
```

每一步运算都返回一个新的 `Value`，同时悄悄记录下了父子关系。为了把这张图看清楚，我们写一个基于 Graphviz 的可视化函数：

```python
# Listing 1.6 用 Graphviz 画出计算图
from graphviz import Digraph

def trace(root):
    nodes, edges = set(), set()
    def build(v):
        if v not in nodes:
            nodes.add(v)
            for child in v._prev:
                edges.add((child, v))
                build(child)
    build(root)
    return nodes, edges

def draw_dot(root):
    dot = Digraph(format='svg', graph_attr={'rankdir': 'LR'})

    nodes, edges = trace(root)
    for n in nodes:
        uid = str(id(n))
        dot.node(name=uid,
                 label="{ %s | data %.4f | grad %.4f }" % (n.label, n.data, n.grad),
                 shape='record')
        if n._op:
            dot.node(name=uid + n._op, label=n._op)
            dot.edge(uid + n._op, uid)

    for n1, n2 in edges:
        dot.edge(str(id(n1)), str(id(n2)) + n2._op)

    return dot
```

`trace` 从根节点出发递归收集所有节点和边；`draw_dot` 把每个节点画成一个矩形，里面依次是名字、数值和梯度，再把运算画成圆点。调用 `draw_dot(L)` 得到的图与 1.2 节的结构图一致。此时所有 `grad` 都是 0，因为还没有做反向传播。

## 1.4 backward：按拓扑序倒着走

反向传播的调用顺序不能乱。一个节点的 `_backward` 只有在**它下游所有节点的梯度都算完**之后才能执行，否则传回来的 `out.grad` 是不完整的。

这个顺序由**拓扑排序**给出：对图做深度优先遍历，先递归处理所有子节点，再把当前节点加入列表。这样得到的列表里，每个节点都排在它的父节点之前；把列表反转，就得到从输出到输入的顺序。

```python
# Listing 1.7 拓扑排序与反向传播（即 Value.backward 的内部逻辑）
def backward(self):
    topo = []
    visited = set()
    def build_topo(v):
        if v not in visited:
            visited.add(v)
            for child in v._prev:
                build_topo(child)
            topo.append(v)
    build_topo(self)

    self.grad = 1.0
    for node in reversed(topo):
        node._backward()
```

`self.grad = 1.0` 是一个常被忽略、但至关重要的初始化：损失对自己的导数当然是 1。它相当于把“1 单位梯度”注入图的末端，之后所有梯度都是相对于这个起点的。

对 `L` 调用 `L.backward()`：

```python
L.backward()
```

得到的梯度是：

| 节点 | data | grad |
| ---- | ---- | ---- |
| a | 2.0 | 6.0 |
| b | -3.0 | -4.0 |
| c | 10.0 | -2.0 |
| e | -6.0 | -2.0 |
| d | 4.0 | -2.0 |
| f | -2.0 | 4.0 |
| L | -8.0 | 1.0 |

可以手工验证几个：$\partial L/\partial f = d = 4$；$\partial L/\partial c = \partial L/\partial d \cdot \partial d/\partial c = f \cdot 1 = -2$；$\partial L/\partial a = f \cdot b = 6$。与 1.2 节的分析完全一致。

至此，一个能工作的自动微分引擎已经成型：**前向时建图，反向时按拓扑序调用局部规则，梯度自动累加**。PyTorch 的 autograd 在原理上与此完全相同，区别只在于它作用于张量而非标量，并且用 C++/CUDA 高效实现。

## 1.5 手算一遍神经元

自动微分引擎只是工具，真正的理解来自亲手推导。这一节我们构建一个最简单的神经元，然后**不用 `backward()`**，一步步手动把梯度算出来，再与引擎的结果对照。

神经元的结构是：输入与权重相乘、求和、加上偏置，最后经过一个非线性激活函数。这里用 $\tanh$：

$$n = x_1 w_1 + x_2 w_2 + b,\qquad o = \tanh(n)$$

```python
# Listing 1.8 一个 tanh 神经元的前向传播
x1 = Value(2.0, label='x1')
x2 = Value(0.0, label='x2')
w1 = Value(-3.0, label='w1')
w2 = Value(1.0, label='w2')
b  = Value(6.8813735870195432, label='b')

x1w1 = x1*w1;                 x1w1.label = 'x1*w1'
x2w2 = x2*w2;                 x2w2.label = 'x2*w2'
x1w1x2w2 = x1w1 + x2w2;       x1w1x2w2.label = 'x1*w1 + x2*w2'
n = x1w1x2w2 + b;             n.label = 'n'
o = n.tanh();                 o.label = 'o'

draw_dot(o)
```

<div style="text-align: center;">
    <img src="Image/ch01/graph-neuron.svg" width="90%" />
</div>

偏置 $b$ 的取值 6.88137... 是刻意凑出来的，目的是让 $n \approx 0.88137$，此时 $\tanh(n) \approx 0.7071$，后续数字比较漂亮。

现在手动反向传播。先给输出设梯度 1：

```python
o.grad = 1.0
```

**第一步：穿过 tanh。** $\tanh$ 的导数是 $1 - \tanh^2(n)$，而 $\tanh(n)$ 正好就是 `o.data`，所以：

```python
o._backward()
# 等价于 n.grad += (1 - o.data**2) * o.grad
```

由于 $o \approx 0.7071$，$1 - o^2 \approx 0.5$，于是 `n.grad = 0.5`。

**第二步：穿过加法 `n = x1w1x2w2 + b`。** 加法的导数原样传回：

```python
n._backward()
```

`x1w1x2w2.grad = 0.5`，`b.grad = 0.5`。

**第三步：穿过加法 `x1w1x2w2 = x1w1 + x2w2`。** 同理：

```python
x1w1x2w2._backward()
```

`x1w1.grad = 0.5`，`x2w2.grad = 0.5`。

**第四步：穿过两个乘法。** 乘法把梯度乘以“对方的值”传给对方：

```python
x1w1._backward()   # x1.grad += w1.data * 0.5；w1.grad += x1.data * 0.5
x2w2._backward()   # x2.grad += w2.data * 0.5；w2.grad += x2.data * 0.5
```

代入数值：

+ `x1.grad = w1.data × 0.5 = -3 × 0.5 = -1.5`
+ `w1.grad = x1.data × 0.5 = 2 × 0.5 = 1.0`
+ `x2.grad = w2.data × 0.5 = 1 × 0.5 = 0.5`
+ `w2.grad = x2.data × 0.5 = 0 × 0.5 = 0.0`

汇总如下：

| 变量 | 值 | 梯度 |
| ---- | -- | ---- |
| x1 | 2.0 | -1.5 |
| x2 | 0.0 | 0.5 |
| w1 | -3.0 | 1.0 |
| w2 | 1.0 | 0.0 |
| b | 6.88137 | 0.5 |
| n | 0.88137 | 0.5 |
| o | 0.70711 | 1.0 |

这些数字有很清晰的物理意义：把 $w_1$ 增加一点点，$o$ 会以 1.0 的速率增加；把 $x_1$ 增加一点点，$o$ 会以 1.5 的速率减小；而 $w_2$ 的梯度是 0，因为对应的输入 $x_2$ 恰好为 0，改变 $w_2$ 对输出没有任何影响。

> [!NOTE]
>
> 表中是手算得到的精确值。直接运行 `o.backward()` 时，浮点运算可能给出 `-1.4999999999999996`、`0.4999999999999999` 这样带尾差的数。它们与 -1.5、0.5 是同一个结果的不同浮点表示，不是代码出错。

这一节的所有代码都可以合并成一句 `o.backward()`。手动拆开只是为了说明：**反向传播没有任何魔法，它只是按顺序执行一串乘法和加法**。下一章我们会看到，PyTorch 对同样的网络算出的梯度与这里逐位一致。

## 1.6 用梯度更新输入

梯度告诉我们“往哪个方向走能让输出变大”。既然 `L` 对 `a` 的梯度是 6，那么把 `a` 增加一个小量，`L` 也会增加约 6 倍的小量。把四个输入都沿梯度方向推一步：

```python
# Listing 1.9 沿梯度方向更新输入
a.data += 0.01 * a.grad
b.data += 0.01 * b.grad
c.data += 0.01 * c.grad
f.data += 0.01 * f.grad

e = a * b
d = e + c
L = d * f
print(L.data)
```

```
-7.286496
```

`L` 从 -8 变成了 -7.2865，确实变大了。

注意这里用的是**加上**梯度。由于我们要让 $L$ 增大，所以沿着梯度方向走；而在训练神经网络时，目标是最小化损失，更新规则会变成 `p.data -= lr * p.grad`，沿梯度**反方向**走。两者的原理相同，只是目标相反。

这一步虽然简单，却已经是梯度下降的全部核心。第 2 章会把它套用到整个多层感知机上，让网络自己学会拟合数据。

## 1.7 为什么梯度要累加

前面反复强调 `_backward` 里要用 `+=`。现在用两个小例子说明原因。

**一个变量被使用两次：**

```python
a = Value(3.0, label='a')
b = a + a; b.label = 'b'
b.backward()
draw_dot(b)
```

<div style="text-align: center;">
    <img src="Image/ch01/graph-a-plus-a.svg" width="55%" />
</div>

$b = a + a = 2a$，所以 $\mathrm{d}b/\mathrm{d}a = 2$。反向传播时，`a` 通过两条边各收到 1 份梯度，累加得到 2。如果写成 `=`，后一次会覆盖前一次，结果变成 1，就错了。

**更一般的菱形结构：**

```python
a = Value(-2.0, label='a')
b = Value(3.0, label='b')
d = a * b; d.label = 'd'
e = a + b; e.label = 'e'
f = d * e; f.label = 'f'
```

$f = ab(a+b)$。从 $a$ 到 $f$ 有两条路径：一条经过 $d$，一条经过 $e$。分别求偏导再相加：

$$\frac{\partial f}{\partial a} = b(a+b) + ab = 3\times 1 + (-2)\times 3 = -3$$

$$\frac{\partial f}{\partial b} = a(a+b) + ab = -2\times 1 + (-2)\times 3 = -8$$

图中 `a.grad = -3`、`b.grad = -8`，与手算一致。这就是多元链式法则：**当同一个变量通过多条路径影响输出时，每条路径的贡献都要累加**。自动微分用 `+=` 实现的，正是这条数学规则。

## 1.8 本章摘要

+ 导数是敏感度：输入变化一个单位，输出变化多少。数值求导用差分近似，简单但只能用于验证。
+ 计算图把复杂表达式拆成只含单个运算的节点，使全局导数可以通过链式法则分解为局部导数的乘积。
+ `Value` 类用 `data` 保存数值、`grad` 保存梯度、`_prev` 记录父子关系、`_backward` 保存局部求导规则，从而在前向计算的同时自动构图。
+ 反向传播按拓扑排序的逆序执行每个节点的 `_backward`，从 `grad = 1` 开始把梯度传回所有输入。
+ 一个 tanh 神经元的梯度可以完全手算：`o.grad = 1`，穿过 tanh 得到 `n.grad = 1 - o²`，再穿过加法和乘法分配下去。
+ 梯度必须用 `+=` 累加，因为同一变量可能通过多条路径影响输出，这是多元链式法则的要求。
+ 沿梯度方向更新输入会让输出增大；最小化损失时则沿反方向更新。
