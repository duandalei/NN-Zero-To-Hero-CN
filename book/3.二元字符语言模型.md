## 3.1 从名字数据集开始

先看看数据长什么样：

```python
# Listing 3.1 载入名字数据集
words = open('names.txt', 'r').read().splitlines()

print(len(words))
print(words[:10])
print(min(len(w) for w in words), max(len(w) for w in words))
```

```
32033
['emma', 'olivia', 'ava', 'isabella', 'sophia', 'charlotte', 'mia', 'amelia', 'harper', 'evelyn']
2 15
```

三万多个人名，最短 2 个字母，最长 15 个。我们的目标是学习这些人名的**字符级分布**，然后生成看起来同样自然的新名字。

字符级建模需要一个特殊的边界符号：在名字开头和结尾各加一个 `.`，表示“文本开始”和“文本结束”。这样一来，名字 `emma` 在模型眼里就是：

```
. e m m a .
```

于是“第一个字母是什么”和“最后一个字母之后是什么”都变成了普通的“给定当前字符，预测下一个字符”问题。把边界符也算进去，词表一共 27 个符号：26 个小写字母加一个 `.`。

## 3.2 统计二元组

最朴素的模型只记住一件事：**当前字符后面最常跟哪个字符**。这就是二元模型（bigram model）。统计方法很直接：遍历所有名字，把每一对相邻字符的出现次数记下来。

```python
# Listing 3.2 用字典统计相邻字符对
b = {}
for w in words:
    chs = ['<S>'] + list(w) + ['<E>']
    for ch1, ch2 in zip(chs, chs[1:]):
        bigram = (ch1, ch2)
        b[bigram] = b.get(bigram, 0) + 1

sorted(b.items(), key=lambda kv: -kv[1])[:8]
```

```
[(('n', '<E>'), 6763),
 (('a', '<E>'), 6640),
 (('a', 'n'), 5438),
 (('<S>', 'a'), 4410),
 (('e', '<E>'), 3983),
 (('a', 'r'), 3264),
 (('e', 'l'), 3248),
 (('r', 'i'), 3033)]
```

这些数字很符合英文人名的直觉：

+ `n` 后面接结尾最多（6763 次），说明很多人名以 n 结尾；
+ `a` 后面接结尾也很多，以 a 结尾的名字同样常见；
+ `a → n` 是最常见字母组合之一，对应 `an` 这样的片段；
+ 名字以 `a` 开头的次数多达 4410，是首字母中的绝对主力。

字典适合探索，但要做矩阵运算和采样，我们需要把它整理成一个规整的二维数组。先建立字符与整数索引的映射：

```python
# Listing 3.3 字符与索引的映射
chars = sorted(list(set(''.join(words))))
stoi = {s: i+1 for i, s in enumerate(chars)}
stoi['.'] = 0
itos = {i: s for s, i in stoi.items()}

print(chars)
print(stoi)
```

```
['a', 'b', 'c', 'd', 'e', 'f', 'g', 'h', 'i', 'j', 'k', 'l', 'm', 'n', 'o', 'p', 'q', 'r', 's', 't', 'u', 'v', 'w', 'x', 'y', 'z']
{'a': 1, 'b': 2, 'c': 3, 'd': 4, 'e': 5, 'f': 6, 'g': 7, 'h': 8, 'i': 9, 'j': 10, 'k': 11, 'l': 12, 'm': 13, 'n': 14, 'o': 15, 'p': 16, 'q': 17, 'r': 18, 's': 19, 't': 20, 'u': 21, 'v': 22, 'w': 23, 'x': 24, 'y': 25, 'z': 26, '.': 0}
```

26 个字母依次编号 1–26，边界符 `.` 固定为 0。接下来创建一个 27×27 的整数矩阵 `N`：行表示当前字符，列表示下一个字符，格子里存出现次数。

```python
# Listing 3.4 用 27×27 矩阵统计二元组
import torch

N = torch.zeros((27, 27), dtype=torch.int32)

for w in words:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        N[stoi[ch1], stoi[ch2]] += 1

print(N[0])
print(N.sum())
```

```
tensor([   0, 4410, 1306, 1542, 1690, 1531,  417,  669,  874,  591, 2422, 2963,
        1572, 2538, 1146,  394,  515,   92, 1639, 2055, 1308,   78,  376,  307,
         134,  535,  929], dtype=torch.int32)
tensor(228146, dtype=torch.int32)
```

第一行对应“以 `.` 开头时，下一个字符是谁”：接 `a` 有 4410 次，接 `k` 有 2963 次，接 `n` 有 2538 次，而接 `.` 本身是 0 次——名字不能是空的。

整个矩阵共有 **228146** 个非零计数，正好等于所有名字的相邻字符对总数。把它画出来是一张漂亮的转移热力图：

## 3.3 从字典到矩阵

计数矩阵还不能直接用来采样，需要把每一行归一化成概率分布：

$$P_{ij} = \frac{N_{ij}}{\sum_j N_{ij}}$$

但直接归一化会遇到一个问题：某些格子的计数为 0，对应的概率就是 0；一旦采样到这些格子，`log(0)` 会变成负无穷，计算损失时直接爆炸。更糟的是，只要训练数据里没出现过的组合，模型就永远认为它不可能出现，这显然过于自信。

解决办法是**拉普拉斯平滑**：给每个格子先加 1，再归一化：

$$P_{ij} = \frac{N_{ij} + 1}{\sum_j (N_{ij} + 1)}$$

```python
# Listing 3.5 计数转概率（加 1 平滑）
P = (N + 1).float()
P /= P.sum(1, keepdims=True)

print(P[0])
print(P[0].sum())
```

```
tensor([0.0000, 0.1376, 0.0408, 0.0481, 0.0527, 0.0478, 0.0130, 0.0209, 0.0273,
        0.0185, 0.0756, 0.0925, 0.0491, 0.0792, 0.0358, 0.0123, 0.0161, 0.0029,
        0.0512, 0.0641, 0.0408, 0.0025, 0.0118, 0.0096, 0.0042, 0.0167, 0.0290])
tensor(1.)
```

`P[0]` 的第一项显示为 0.0000，但它并不是精确的 0：原始计数是 0，加上 1 之后变成 $1 / (4410+1306+\cdots+27) \approx 3 \times 10^{-5}$，只是四舍五入后看不见了。这正体现了平滑的作用——**给从未出现的组合留一条极细的活路**。

`keepdims=True` 让求和结果保持 `(27, 1)` 的形状，从而能按行广播相除。PyTorch 同时接受 `keepdims` 和 `keepdim` 两种写法。

## 3.4 采样：让模型起名字

有了每一行的概率分布，就可以像掷骰子一样生成名字：从 `.`（索引 0）出发，按当前行的概率抽下一个字符，直到抽到 `.` 为止。

```python
# Listing 3.6 从二元模型采样
g = torch.Generator().manual_seed(2147483647)

for i in range(5):
    out = []
    ix = 0
    while True:
        p = P[ix]
        ix = torch.multinomial(p, num_samples=1,
                               replacement=True, generator=g).item()
        out.append(itos[ix])
        if ix == 0:
            break
    print(''.join(out))
```

```
cexze.
momasurailezitynn.
konimittain.
llayn.
ka.
```

`torch.multinomial` 按照给定的概率分布进行有放回抽样；固定 `Generator` 的种子后，整个序列可以复现。

生成的名字“有点像名字”，但明显不对劲：`cexze` 开头就很别扭，`momasurailezitynn` 长得离谱。原因很容易理解：二元模型只看**前一个字符**。它知道 `q` 后面几乎总是 `u`，却不知道一个名字已经出现了几个字母、当前处于词首还是词尾。要生成更自然的名字，模型必须记住更长的上下文——这是第 4 章的主题。

> **注意**
>
> **为什么你的采样结果可能不同？**
>
> 即使使用相同的随机种子，不同版本的 PyTorch 也可能给出不同的采样序列——`torch.multinomial` 的实现细节会随版本变化。这不影响模型本身的概率分布，只影响“掷骰子”的具体顺序。

## 3.5 用负对数似然评估模型

采样只能定性感受模型好坏。要定量评估，需要一个能比较不同模型的指标。

语言模型的目标是最大化训练数据的似然：对每个名字，模型给它的概率越高越好。整个数据集的似然是每个字符概率的乘积：

$$L = \prod_{t} P(x_{t+1} \mid x_t)$$

乘积很容易下溢成 0，而且不便于求导。取对数后，乘积变成求和，单调性不变：

$$\log L = \sum_t \log P(x_{t+1} \mid x_t)$$

训练时通常取相反数再求平均，得到**平均负对数似然**（average negative log likelihood，NLL）：

$$\text{NLL} = -\frac{1}{n}\sum_t \log P(x_{t+1} \mid x_t)$$

NLL 越小，模型给正确字符分配的概率越高。它还有一条重要性质：**就是交叉熵**，因此可以直接作为分类任务的损失函数。

```python
# Listing 3.7 计算二元模型的平均 NLL
log_likelihood = 0.0
n = 0

for w in words:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        prob = P[stoi[ch1], stoi[ch2]]
        log_likelihood += torch.log(prob)
        n += 1

print(f'{log_likelihood=}')
nll = -log_likelihood
print(f'{nll=}')
print(f'{nll/n}')
```

```
log_likelihood=tensor(-559951.5625)
nll=tensor(559951.5625)
nll/n=2.4543561935424805
```

228146 个相邻对，总负对数似然约 55.995 万，平均每个字符 **2.4544**。把它转换成更直观的**困惑度**（perplexity）：

$$\text{perplexity} = e^{2.4544} \approx 11.64$$

困惑度可以理解为“模型每一步平均在多少个字符之间犹豫”。词表有 27 个字符，完全瞎猜的困惑度是 27；二元模型把它降到了 11.64，说明它确实学到了不少结构。

## 3.6 用神经网络重写二元模型

刚才的计数模型简单有效，但它有一个明显的局限：它是一张**查表**。如果词表扩大、上下文变长，表格会爆炸式增长。而神经网络可以用参数共享的方式表达同样的分布，并且能自然地扩展到更长的上下文。

有趣的是，二元模型完全可以用一个极简的神经网络表示：**输入字符的 one-hot 向量，乘以一个 27×27 的权重矩阵，再经过 softmax**。

先构造训练集。每个相邻字符对就是一个样本：当前字符是输入，下一个字符是标签。

```python
# Listing 3.8 构造 (输入, 标签) 数据集
xs, ys = [], []

for w in words:
    chs = ['.'] + list(w) + ['.']
    for ch1, ch2 in zip(chs, chs[1:]):
        xs.append(stoi[ch1])
        ys.append(stoi[ch2])

xs = torch.tensor(xs)
ys = torch.tensor(ys)
print(xs[:5])
print(ys[:5])
print(xs.nelement())
```

```
tensor([ 0,  5, 13, 13,  1])
tensor([ 5, 13, 13,  1,  0])
228146
```

第一个名字 `emma` 展开为 `. e m m a .`，对应五组样本：`(0→5)`、`(5→13)`、`(13→13)`、`(13→1)`、`(1→0)`，正是 `.e`、`em`、`mm`、`ma`、`a.`。

把输入索引变成 one-hot 向量：

```python
# Listing 3.9 one-hot 编码
import torch.nn.functional as F

xenc = F.one_hot(xs, num_classes=27).float()
print(xenc.shape)
```

```
torch.Size([228146, 27])
```

每一个输入都是长度为 27 的向量，只有对应字符的位置是 1，其余为 0。把那 5 个样本画出来，可以看到每一行只有一个亮点：

<div style="text-align: center;">
    <img src="Image/ch03/one-hot.png?v=2" width="55%" />
</div>

它乘上权重矩阵 `W` 时，效果等价于“取出 `W` 的某一行”：

$$(5, 27) \times (27, 27) \longrightarrow (5, 27)$$

用一个 5 个样本的小例子看前向传播：

```python
# Listing 3.10 神经网络版二元模型的前向传播
g = torch.Generator().manual_seed(2147483647)
W = torch.randn((27, 27), generator=g, requires_grad=True)

xenc = F.one_hot(xs[:5], num_classes=27).float()
logits = xenc @ W          # 每个字符对应的 27 个分数
counts = logits.exp()      # 相当于“计数”
probs = counts / counts.sum(1, keepdims=True)   # softmax

loss = -probs[torch.arange(5), ys[:5]].log().mean()
print(loss.item())
```

```
3.7693049907684326
```

最后两行 `exp` 再归一化，合起来就是 **softmax**。它把任意实数分数变成和为 1 的正概率分布。`logits` 因此可以理解为“对数计数”：取指数后得到类似计数矩阵 `N` 的正数，再归一化就得到概率。

这个网络的参数只有 `W` 的 27×27 = 729 个。每一行对应一个输入字符，独立决定下一个字符的分布——**行与行之间没有任何交互**。所以它虽然穿着神经网络的外衣，本质上仍然是一个二元模型。

## 3.7 梯度下降训练

现在用全部 228146 个样本做全批量梯度下降。损失由两部分组成：平均 NLL，加上一个 L2 正则项。

```python
# Listing 3.11 训练神经网络版二元模型
g = torch.Generator().manual_seed(2147483647)
W = torch.randn((27, 27), generator=g, requires_grad=True)

xenc = F.one_hot(xs, num_classes=27).float()
num = xs.nelement()

for k in range(200):

    # 前向传播
    logits = xenc @ W
    counts = logits.exp()
    probs = counts / counts.sum(1, keepdims=True)
    loss = -probs[torch.arange(num), ys].log().mean() + \
           0.01 * (W**2).mean()

    # 反向传播
    W.grad = None
    loss.backward()

    # 更新
    W.data += -50 * W.grad
```

逐行解释几个关键点：

+ **全批量**：每一步都用全部 228146 个样本计算损失和梯度。这比小批量慢，但对这个规模的数据完全可行，而且梯度方向更稳定。
+ **`W.grad = None`**：PyTorch 的梯度默认累加，必须在每次反向传播前清零。等价于 `optimizer.zero_grad()`。
+ **学习率 50**：看起来很大，但因为损失是 228146 个样本的平均，单样本梯度被平均稀释了，实际步长是合理的。
+ **L2 正则**：`0.01 * (W**2).mean()` 惩罚过大的权重，防止模型对训练数据过度自信。它的作用与计数模型里的加 1 平滑类似——都是给概率分布“留余地”。

## 3.8 训练结果与讨论

为了看清这个模型到底学到了什么，我们做三组对比。

**第一组：去掉正则，训练更久。** 不加重正则项时，网络会收敛到与计数模型完全相同的极大似然解：

| 训练步数 | 平均 NLL（无正则） |
| -------- | ------------------ |
| 0 | 3.7590 |
| 200 | 2.4624 |
| 500 | 2.4570 |
| 1000 | 2.4554 |
| 2000 | 2.4546 |
| 5000 | 2.4543 |

计数模型（加 1 平滑）的 NLL 是 2.4544；不加平滑的极大似然解是 2.4540。无正则的网络最终收敛到 2.4543，几乎精确地复现了计数模型——这印证了理论：**one-hot + 线性层 + softmax 就是二元模型的参数化形式**，两者在最优解处等价。

**第二组：保留正则。** 正则项会让网络停在略高的位置。2000 步后，打印出来的总损失是 2.4804，其中 NLL 部分是 2.4604，正则项约 0.0200。正则把概率分布往均匀方向拉了一点，所以 NLL 比无正则时更高。这不是“训练失败”，而是用一点拟合精度换取更平滑、更不容易过拟合的分布。

**第三组：用训练好的网络采样。** 无正则模型训练 2000 步后，用同样的种子采样：

```
cexze.
momasurailezitynn.
konimittain.
llayn.
ka.
```

与 3.4 节计数模型生成的名字**完全一致**。这不是巧合：两个模型的概率分布已经几乎相同，同样的随机数序列自然走出同样的路径。而带正则的模型因为分布被轻微压平，采样结果会略有不同（例如 `momasurailezityha.`）。

这个结果很有启发性：我们用梯度下降训练了一个“神经网络”，得到的却是一个可以用 27×27 表格表达的二元模型。**神经网络的威力不在于把二元模型做得更好，而在于它提供了可扩展的框架**：把输入从单个字符换成多个字符的拼接，加一层隐藏层和非线性，就能表达远比查表丰富的函数。这正是下一章要做的事。

## 3.9 本章摘要

+ 字符级语言模型把文本看作字符序列，用 `.` 标记序列的开头和结尾，词表共 27 个符号。
+ 二元模型只根据前一个字符预测下一个字符，统计上等价于一张 27×27 的转移计数矩阵；整个数据集共有 228146 个相邻对。
+ 计数矩阵需要按行归一化成概率；加 1 平滑避免零概率，共有 102 个从未出现的字符对。
+ 从概率分布中采样可以生成新名字，`torch.multinomial` 配合固定种子保证可复现，但不同 PyTorch 版本的采样序列可能不同。
+ 平均负对数似然（NLL）是语言模型的标准评估指标；二元模型的 NLL 为 2.4544，困惑度约 11.64。
+ one-hot + 线性层 + softmax 构成了二元模型的神经网络实现；训练时最小化 NLL，L2 正则起到与平滑类似的作用。
+ 无正则的网络在足够多步后收敛到与计数模型相同的 NLL（约 2.454），带正则时停在略高处。
+ 二元模型的根本局限是上下文只有一个字符；要生成更自然的名字，必须让模型看到更长的历史。
