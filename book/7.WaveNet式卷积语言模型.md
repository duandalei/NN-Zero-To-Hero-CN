第 6 章的模型已经能生成相当自然的名字，但它只看三个字符。三个字符足以判断 `q` 后面该跟 `u`，却不足以把握一个名字的整体节奏：开头、中间、结尾的音节结构，以及哪些辅音组合允许出现、哪些不允许。

这一章把上下文扩展到 **8 个字符**，并引入一种层次化的结构：先把相邻的两个字符合并，再把合并后的结果两两合并，如此反复。这个结构正是 WaveNet 的核心思想——**用逐层扩大的感受野处理序列**。它也为下一站的 Transformer 铺好了路。

## 7.1 更长的上下文

把 `block_size` 从 3 改成 8。数据集构造方式不变，只是窗口更长：

```python
# Listing 7.1 构造 8 字符上下文
block_size = 8

def build_dataset(words):
    X, Y = [], []
    for w in words:
        context = [0] * block_size
        for ch in w + '.':
            ix = stoi[ch]
            X.append(context)
            Y.append(ix)
            context = context[1:] + [ix]
    return torch.tensor(X), torch.tensor(Y)
```

打乱后的第一个名字 `yuheng` 展开成：

| 上下文 | 目标 |
| ------ | ---- |
| `........` | y |
| `.......y` | u |
| `......yu` | h |
| `.....yuh` | e |
| `....yuhe` | n |
| `...yuhen` | g |
| `..yuheng` | . |

数据规模与之前相同：训练集 182625 个样本，验证集 22655 个，测试集 22866 个。变的只是每个样本的上下文长度：从 3 个索引变成 8 个索引。

上下文变长后，一个自然的想法是：把 8 个字符的嵌入向量直接拼接成一个长向量，送进一个大的线性层。这样做能工作，但有两个问题。

## 7.2 朴素展平

假设嵌入维度是 24，8 个字符拼接后是 192 维。如果直接接一个 192→128 的线性层，参数量是 $192\times128=24576$，比 3 字符模型的 30→200 还多。而且这 192 个输入中的每一个位置都有自己独立的一列权重：模型把“第 1 个字符”“第 2 个字符”……当成完全不同的特征，没有利用它们之间的相似性。

更本质的问题是：**位置与位置之间是对称的**。`...abc` 和 `..abc.` 中的 `abc` 应该用同一套规则处理，但朴素展平会为每个位置学一套独立的权重。数据量有限时，这会导致每个位置的权重都学不充分。

我们希望网络满足两个性质：

1. **参数共享**：同一套规则应用到所有位置；
2. **层次组合**：先把相邻的字符合并成短片段，再把片段合并成更长的片段。

这两个性质正好对应卷积网络的设计。

## 7.3 分层展平

先看新引入的 `FlattenConsecutive`：

```python
# Listing 7.2 FlattenConsecutive：把相邻的 n 个时间步合并
class FlattenConsecutive:
    def __init__(self, n):
        self.n = n

    def __call__(self, x):
        B, T, C = x.shape
        x = x.view(B, T // self.n, C * self.n)
        if x.shape[1] == 1:
            x = x.squeeze(1)
        self.out = x
        return self.out

    def parameters(self):
        return []
```

输入形状是 `(B, T, C)`：批次、时间步、每个时间步的特征数。它把相邻的 `n` 个时间步拼成一个更长的特征向量，时间步数缩小为 `T/n`，特征数扩大为 `C*n`。如果只剩下一个时间步，就把这一维挤掉，变成二维张量。

把它和 `Linear`、`BatchNorm1d`、`Tanh` 组合起来：

```python
# Listing 7.3 WaveNet 风格的分层网络
n_embd, n_hidden = 24, 128

model = Sequential([
    Embedding(vocab_size, n_embd),
    FlattenConsecutive(2), Linear(n_embd * 2, n_hidden, bias=False), BatchNorm1d(n_hidden), Tanh(),
    FlattenConsecutive(2), Linear(n_hidden * 2, n_hidden, bias=False), BatchNorm1d(n_hidden), Tanh(),
    FlattenConsecutive(2), Linear(n_hidden * 2, n_hidden, bias=False), BatchNorm1d(n_hidden), Tanh(),
    Linear(n_hidden, vocab_size),
])

with torch.no_grad():
    model.layers[-1].weight *= 0.1

parameters = model.parameters()
for p in parameters:
    p.requires_grad = True
```

形状的变化如下（以一个批次 4 个样本为例）：

| 层 | 输出形状 | 说明 |
| -- | -------- | ---- |
| Embedding | (4, 8, 24) | 8 个字符，每个 24 维 |
| FlattenConsecutive(2) | (4, 4, 48) | 两两合并 |
| Linear + BN + Tanh | (4, 4, 128) | 每个位置独立变换 |
| FlattenConsecutive(2) | (4, 2, 256) | 四个合并成两个 |
| Linear + BN + Tanh | (4, 2, 128) | |
| FlattenConsecutive(2) | (4, 256) | 两个合并成一个 |
| Linear + BN + Tanh | (4, 128) | |
| Linear | (4, 27) | 输出 27 类 logits |

三个 `Linear` 层的权重形状分别是 48×128、256×128、256×128，最后一个 128×27。参数量为 **76579**。

注意 `Linear` 作用在三维张量的最后一维上：`(B, T, C) @ (C, D) → (B, T, D)`。同一个权重矩阵被应用到所有时间步，这就是**参数共享**。正因为如此，第一层看到的 2 个字符、第二层看到的 4 个字符、第三层看到的 8 个字符，用的是同一套组合规则。

这种结构可以看作一个**感受野逐层扩大的卷积网络**：

+ 第一层每个位置看到 2 个字符；
+ 第二层把两个 2 字符片段组合，看到 4 个字符；
+ 第三层把两个 4 字符片段组合，看到全部 8 个字符。

这正是 WaveNet 中“膨胀卷积”（dilated convolution）的思想。它不是把 8 个字符一次性摊平，而是逐层建立越来越大的上下文。

## 7.4 三维张量与批归一化

分层结构带来了一个工程细节：中间层的张量是三维的 `(B, T, C)`，而第 5 章的 `BatchNorm1d` 只处理二维输入。

批归一化应该对哪个维度求均值？对卷积层，标准做法是**对批次和时间步一起归一化**，每个通道单独统计。也就是说，对形状 `(B, T, C)` 的张量，在维度 0 和 1 上求均值和方差：

```python
# Listing 7.4 支持三维输入的 BatchNorm1d
class BatchNorm1d:
    def __call__(self, x):
        if self.training:
            if x.ndim == 2:
                dim = 0
            elif x.ndim == 3:
                dim = (0, 1)
            xmean = x.mean(dim, keepdim=True)
            xvar = x.var(dim, keepdim=True)
        else:
            xmean = self.running_mean
            xvar = self.running_var
        xhat = (x - xmean) / torch.sqrt(xvar + self.eps)
        self.out = self.gamma * xhat + self.beta
        if self.training:
            with torch.no_grad():
                self.running_mean = (1 - self.momentum) * self.running_mean + self.momentum * xmean
                self.running_var = (1 - self.momentum) * self.running_var + self.momentum * xvar
        return self.out
```

对三维输入在 `(0, 1)` 上归一化后，统计量的形状是 `(1, 1, C)`，可以自然地广播回 `(B, T, C)`。如果只对维度 0 归一化，每个时间步会有自己的一套统计量，这不符合“同一通道在所有位置共享统计”的卷积假设。

`FlattenConsecutive` 在只剩一个时间步时会 `squeeze(1)`，把 `(B, 1, C)` 变回 `(B, C)`，因此后面的 `Linear` 和 BN 会自动切回二维模式。这个细节让同一个类可以同时处理两种形状。

## 7.5 训练结果

训练设置与之前相同：batch size 32，10 万步，学习率前 7.5 万步为 0.1，之后为 0.01。

```python
# Listing 7.5 训练循环
for i in range(100000):
    ix = torch.randint(0, Xtr.shape[0], (32,))
    Xb, Yb = Xtr[ix], Ytr[ix]

    logits = model(Xb)
    loss = F.cross_entropy(logits, Yb)

    for p in parameters:
        p.grad = None
    loss.backward()

    lr = 0.1 if i < 75000 else 0.01
    for p in parameters:
        p.data += -lr * p.grad
```

## 7.6 卷积就是 for 循环

章节开头说这是“WaveNet 式”的模型，但代码里没有任何 `Conv1d`。为什么？

因为**在序列上滑动一个共享权重的线性层，就是卷积**。考虑下面这段对比代码：

```python
# Listing 7.6 逐样本前向与批量前向
logits = model(Xtr[7:15])          # 一次处理 8 个样本
print(logits.shape)                # (8, 27)

stacked = torch.zeros(8, 27)
for i in range(8):
    stacked[i] = model(Xtr[[7 + i]])   # 逐个处理
print((logits - stacked).abs().max())
```

实测两者完全相同，最大差异为 **2.38e-06**。`model(Xtr[7:15])` 里并没有一个显式的循环：它是把 8 个样本堆成一个批次，让 `Linear` 在时间和批次维度上并行计算。但数学上，它与“对每个位置分别应用同一个线性层”完全等价。

这就是卷积的本质：

+ 一个卷积核在序列上滑动，每个位置都用同一组权重；
+ 卷积可以写成矩阵乘法，也可以通过 `unfold` 变成一个大矩阵乘法；
+ “批处理”只是把多个位置放进同一个张量，让硬件一次算完。

`FlattenConsecutive(2)` + `Linear` 的组合，等价于一个核大小为 2、步长为 2 的一维卷积。三层堆叠起来，感受野依次是 2、4、8——与 WaveNet 的膨胀卷积结构一致。区别只在于 WaveNet 使用更大的核和更精细的膨胀率，而这里用最朴素的两两合并来演示同样的思想。

理解了这一点，就能明白为什么卷积网络在序列任务上如此高效：**参数共享让每个位置复用同一套规则，批处理让所有位置并行计算**。Transformer 的自注意力也是沿着这个方向继续演化——不仅共享参数，还让每个位置动态地决定该关注哪些位置。

## 7.7 本章摘要

+ 把上下文从 3 扩展到 8 个字符，模型能利用更长的历史，验证损失进一步下降。
+ 朴素展平把 8 个字符拼成一个长向量，参数随上下文线性增长，而且每个位置有独立权重，无法共享规则。
+ `FlattenConsecutive(2)` 把相邻时间步两两合并，配合共享权重的 `Linear`，逐层把感受野从 2 扩大到 4、再到 8。
+ 这种分层结构就是 WaveNet 式膨胀卷积的简化版；参数量为 76579，验证损失约 1.9890。
+ 三维张量的 BN 要在批次和时间维度 `(0, 1)` 上归一化，每个通道共享统计量；`squeeze` 让网络在最后自动切回二维。
+ 批处理前向与逐样本循环前向在数学上完全等价——“卷积就是一个 for 循环”，只是把循环交给了张量运算并行执行。
+ 8 字符模型开始出现过拟合迹象（训练/验证差距约 0.155），但验证损失仍在下降，模型容量与上下文长度都还有提升空间。
