第 3 章的二元模型只看前一个字符，生成的名字经常出现 `cexze`、`momasurailezitynn` 这种奇怪的组合。问题不在于训练不够，而在于**信息不足**：只看一个字符，模型无法知道名字已经进行到第几个字母，也无法区分词首、词中和词尾。

这一章给模型三个字符的上下文。为了处理这三个字符，我们会引入两个新组件：**嵌入层**把离散的字符索引变成稠密向量，**隐藏层**把这些向量组合成更抽象的特征。两者合起来，就是一个多层感知机（MLP）语言模型。

## 4.1 让模型看到三个字符

把上下文长度设为 3。对每个名字，我们从三个边界符 `.` 开始，每次读取一个字符，预测下一个字符，然后把窗口向右滑动一格。

以打乱后的第一个训练名字 `yuheng` 为例（`random.seed(42)` 后实测）：

| 上下文 | 目标字符 |
| ------ | -------- |
| `...` | y |
| `..y` | u |
| `.yu` | h |
| `yuh` | e |
| `uhe` | n |
| `hen` | g |
| `eng` | . |

最后一行预测的是结束符 `.`，表示名字到此为止。七个训练样本覆盖了 `yuheng` 的整个生成过程。

用代码构造整个数据集：

```python
# Listing 4.1 构造上下文窗口数据集
block_size = 3   # 上下文长度

def build_dataset(words):
    X, Y = [], []
    for w in words:
        context = [0] * block_size
        for ch in w + '.':
            ix = stoi[ch]
            X.append(context)          # 当前窗口
            Y.append(ix)               # 下一个字符
            context = context[1:] + [ix]   # 窗口右移
    return torch.tensor(X), torch.tensor(Y)
```

`X` 的每一行是三个字符的索引，`Y` 是对应的下一个字符索引。因为词表是 27 个符号，所有索引都在 0–26 之间。

上下文长度为什么选 3？这是一个工程折中。上下文越长，模型能利用的信息越多；但输入维度也随之增长，参数和计算量都会增加。3 个字符足以覆盖大量常见的英文片段，又足够小，便于在笔记本上训练。第 7 章会用更结构化的方式处理更长的上下文。

## 4.2 划分数据集

训练之前先划分数据。我们不能用训练数据来评估模型——模型可以把训练集背下来，分数很好看，但遇到新名字就会露馅。标准做法是留出一部分数据专门做评估：

+ **训练集**：用来更新参数，占 80%
+ **验证集**：用来调超参数、观察是否过拟合，占 10%
+ **测试集**：只在最后评估一次，占 10%

```python
# Listing 4.2 打乱并划分数据
import random

random.seed(42)
random.shuffle(words)
n1 = int(0.8 * len(words))
n2 = int(0.9 * len(words))

Xtr, Ytr = build_dataset(words[:n1])
Xdev, Ydev = build_dataset(words[n1:n2])
Xte, Yte = build_dataset(words[n2:])
```

实测的数据规模：

```
torch.Size([182625, 3]) torch.Size([182625])
torch.Size([22655, 3])  torch.Size([22655])
torch.Size([22866, 3])  torch.Size([22866])
```

三个集合加起来正好 228146 个样本，与第 3 章的相邻字符对总数一致。

>
> 原 notebook 记录的划分结果是 182441 / 22902 / 22803。一种可能的解释是：那一格在 Jupyter 中被重复执行过，`words` 在上一次执行后已经打乱，再次执行时 `random.seed(42)` 后打乱的是“已经打乱过的列表”，于是得到另一个排列。本书的结果来自对原始有序列表的第一次打乱，是可复现的干净结果。

## 4.3 嵌入层

第 3 章用 one-hot 向量表示字符：27 维，只有一位是 1。这种做法在这个小模型里能工作，但有两个缺点：维度固定且稀疏；不同字符之间没有任何“相似性”的概念。

更常用的做法是**嵌入**（embedding）：给每个字符分配一个可学习的稠密向量。词表有 27 个符号，设嵌入维度为 10，就得到一个 27×10 的矩阵 `C`：

```python
# Listing 4.3 字符嵌入矩阵
n_embd = 10

g = torch.Generator().manual_seed(2147483647)
C = torch.randn((27, n_embd), generator=g)

emb = C[Xtr]
print(emb.shape)          # (182625, 3, 10)
```

`C[Xtr]` 是一次**查表**：把 `Xtr` 中每个索引替换成 `C` 的对应行。结果的形状是 `(样本数, 上下文长度, 嵌入维度)`，即每个样本的三个字符各自变成一个 10 维向量。

接下来把三个向量拼接起来，得到 30 维输入：

```python
embcat = emb.view(emb.shape[0], -1)
print(embcat.shape)       # (182625, 30)
```

`view(..., -1)` 把后两维展平。`-1` 让 PyTorch 自动推断这一维的大小：3×10=30。

嵌入与 one-hot 并不是互斥的。`one_hot(x) @ C` 与 `C[x]` 在数学上完全等价，都是取出第 x 行；但 one-hot 需要先构造一个 27 维稀疏向量再做矩阵乘法，而嵌入查找直接定位到对应的行，效率高得多。更重要的是，嵌入向量是**可学习**的：训练之后，用法相似的字符会得到相近的向量，这一点在 4.7 节会直观地看到。

## 4.4 搭建 MLP

现在把 30 维输入送进一个带隐藏层的网络：

```
30 维输入 → 线性层 (30×200) → tanh → 线性层 (200×27) → softmax → 27 类概率
```

```python
# Listing 4.4 一个隐藏层的 MLP
n_hidden = 200

W1 = torch.randn((n_embd * block_size, n_hidden), generator=g)
b1 = torch.randn(n_hidden, generator=g)
W2 = torch.randn((n_hidden, vocab_size), generator=g)
b2 = torch.randn(vocab_size, generator=g)

parameters = [C, W1, b1, W2, b2]
for p in parameters:
    p.requires_grad = True

# 取一个小批量（训练循环中会重复这一步）
ix = torch.randint(0, Xtr.shape[0], (32,))
Xb, Yb = Xtr[ix], Ytr[ix]

# 前向传播
emb = C[Xb]                              # (32, 3, 10)
h = torch.tanh(emb.view(-1, 30) @ W1 + b1)   # (32, 200)
logits = h @ W2 + b2                     # (32, 27)
loss = F.cross_entropy(logits, Yb)
```

形状变化如下：

| 步骤 | 形状 | 说明 |
| ---- | ---- | ---- |
| `emb = C[Xb]` | (32, 3, 10) | 每个样本三个字符，每个字符 10 维 |
| `emb.view(-1, 30)` | (32, 30) | 展平 |
| `@ W1 + b1` | (32, 200) | 隐藏层预激活 |
| `tanh` | (32, 200) | 非线性 |
| `@ W2 + b2` | (32, 27) | 每个字符的 logits |
| `cross_entropy` | 标量 | 平均损失 |

参数总量：

| 参数 | 形状 | 数量 |
| ---- | ---- | ---- |
| C | 27×10 | 270 |
| W1 | 30×200 | 6000 |
| b1 | 200 | 200 |
| W2 | 200×27 | 5400 |
| b2 | 27 | 27 |
| 合计 | | **11897** |

与第 3 章的 729 个参数相比，模型大了十几倍，但它能利用三个字符的上下文，表达能力不可同日而语。

这里用 `F.cross_entropy` 而不是手写 `softmax + log + mean`。两者在数学上等价，但 PyTorch 的实现把 `log_softmax` 和负对数似然融合在一起，数值上更稳定，也不会因为概率过小而出现 `log(0)`。

> **注意**
>
> **糟糕的初始化**
>
> 上面的 `W1` 和 `W2` 直接用了标准正态分布。`W1` 有 30 个输入，输出方差大约是 30；`W2` 有 200 个输入，输出方差大约是 200。两者叠加，初始 logits 的绝对值会非常大，softmax 变得极度自信，交叉熵损失高达 **24.05**（实测第一步）。这不是模型坏了，而是初始化尺度没有控制好。第 5 章会系统处理这个问题：缩放初始权重、加入批归一化。

## 4.5 小批量训练

数据有 18 万个样本，每一步都算全量梯度太慢。改用**小批量**（minibatch）：每次随机抽 32 个样本，用这一小批估计梯度，更新一次参数。梯度的方向会有噪声，但计算快得多，而且噪声本身有助于跳出糟糕的局部区域。

```python
# Listing 4.5 小批量训练
for i in range(200000):

    # 抽取一个小批量
    ix = torch.randint(0, Xtr.shape[0], (32,))
    Xb, Yb = Xtr[ix], Ytr[ix]

    # 前向传播
    emb = C[Xb]
    h = torch.tanh(emb.view(-1, 30) @ W1 + b1)
    logits = h @ W2 + b2
    loss = F.cross_entropy(logits, Yb)

    # 反向传播
    for p in parameters:
        p.grad = None
    loss.backward()

    # 更新：前 10 万步用 0.1，之后用 0.01
    lr = 0.1 if i < 100000 else 0.01
    for p in parameters:
        p.data += -lr * p.grad
```

三个细节：

+ **`torch.randint` 有放回抽样**：同一个小批量里可能出现重复样本，这没关系；小批量只是梯度的估计。
+ **`p.grad = None`**：每次反向传播前清空梯度，原因与第 2 章相同。
+ **学习率衰减**：前 10 万步用 0.1 快速下降，后 10 万步降到 0.01 精细调整。如果一直用 0.1，损失会在最优点附近来回跳动，降不下去。

训练过程中记录的小批量损失（实测）：

| 步数 | 损失 |
| ---- | ---- |
| 0 | 24.0535 |
| 999 | 3.4725 |
| 9999 | 2.7817 |
| 49999 | 2.4798 |
| 99999 | 2.5214 |
| 149999 | 1.5811 |
| 199999 | 2.0169 |

小批量损失本身波动很大——每一步只用了 32 个样本，单个难样本就能把损失拉高。看图时应该关注整体趋势，而不是某一步的高低。

## 4.6 训练结果

训练结束后，在三个集合上计算完整损失：

```python
@torch.no_grad()
def split_loss(split):
    x, y = {
        'train': (Xtr, Ytr),
        'val': (Xdev, Ydev),
        'test': (Xte, Yte),
    }[split]
    emb = C[x]
    h = torch.tanh(emb.view(-1, 30) @ W1 + b1)
    logits = h @ W2 + b2
    loss = F.cross_entropy(logits, y)
    print(split, loss.item())

split_loss('train')
split_loss('val')
split_loss('test')
```

实测结果：

```
train 2.1253974437713623
val 2.1678714752197266
test 2.1673572063446045
```

三个数字非常接近，验证集和测试集只比训练集高一点点（约 0.04），说明模型**没有明显过拟合**。这并不意外：训练集有 18 万个样本，而模型只有 11897 个参数，数据量远大于模型容量。

与第 3 章的二元模型对比：

| 模型 | 上下文 | 平均 NLL |
| ---- | ------ | -------- |
| 二元计数模型 | 1 个字符 | 2.4544 |
| 本文 MLP | 3 个字符 | 2.1679（验证集） |

从 2.45 降到 2.1 左右，是一个实质性的进步。多出来的两个字符让模型能区分 `...`（词首）、`..a`、`a..` 等不同位置，也能利用 `an`、`in` 这样的常见片段。

训练完成后，嵌入矩阵 `C` 的每一行就是一个字符的 10 维向量。取前两维画散点图，可以直观地观察字符之间的关系：

图中可以看到一些有趣的结构：元音字母往往聚在一起，辅音字母形成另一片区域，边界符 `.` 则常出现在与词首、词尾行为相关的位置。需要强调的是，这只是 10 维空间的二维投影，距离的解读要谨慎；但训练确实让“用法相似”的字符靠得更近。

这些向量不是人工设计的，也没有使用任何预训练模型。它们从随机初始值开始，仅仅通过“预测下一个字符”这个任务，就自己组织出了有意义的几何结构。这正是表示学习的核心思想——**好的特征可以由下游任务自动学出来**。

## 4.8 采样

训练好的模型可以用来生成新名字。采样过程与二元模型相同，只是每次需要把三个字符的上下文送进 MLP：

```python
# Listing 4.6 从 MLP 采样
g = torch.Generator().manual_seed(2147483647 + 10)

for _ in range(20):
    out = []
    context = [0] * block_size
    while True:
        emb = C[torch.tensor([context])]        # (1, 3, 10)
        h = torch.tanh(emb.view(1, -1) @ W1 + b1)
        logits = h @ W2 + b2
        probs = F.softmax(logits, dim=1)
        ix = torch.multinomial(probs, num_samples=1, generator=g).item()
        context = context[1:] + [ix]
        out.append(ix)
        if ix == 0:
            break
    print(''.join(itos[i] for i in out))
```

但问题仍然存在：有些名字读起来还是别扭，偶尔会出现不自然的辅音簇。三个字符的上下文仍然太短，而且所有字符位置共用同一组权重，模型不知道“这是第几个字母”。第 5 章会从训练稳定性和激活值分布入手，第 7 章则会引入能处理更长上下文的卷积结构。

## 4.9 本章摘要

+ 把上下文从 1 个字符扩展到 3 个字符，模型就能区分词首、词中和词尾，表达能力显著增强。
+ 数据按 80/10/10 划分为训练集、验证集和测试集；验证集用于调参，测试集只在最后评估一次。
+ 嵌入层把字符索引映射为可学习的稠密向量；`C[X]` 是一次查表，等价于 one-hot 乘 `C`，但更高效。
+ 三个 10 维嵌入拼接成 30 维输入，经过 30→200→27 的 MLP，参数量为 11897。
+ 小批量梯度下降每步只用 32 个样本，配合学习率从 0.1 衰减到 0.01，训练 20 万步。
+ 训练集、验证集、测试集损失接近，说明模型没有明显过拟合；验证损失约 2.1，明显优于二元模型的 2.45。
+ 嵌入空间呈现出一定的结构，说明字符向量通过预测任务学到了用法上的相似性。
+ 采样得到的名字比二元模型自然得多，但三字符上下文仍然有限，这为后续的批归一化与更长上下文模型埋下伏笔。
